## Критические требования

| Требование | Подтверждение |
|---|---|
| User: идентификатор, логин, хеш, роль | `Domain/Entities/User.cs`; валидация и закрытые сеттеры |
| Booking связан с пользователем | Обязательный UserId, FK в PostgreSQL, индекс UserId/Status, новая миграция |
| Запрет бронирования начавшегося события | StartAt <= UTC now → EventAlreadyStartedException → 400; юнит- и HTTP-тесты |
| Не более 10 активных броней пользователя | Считаются Pending и Confirmed по всем событиям; 11-я → 409; проверена конкурентность и независимость пользователей |
| Права на отмену | Владелец или Admin; чужой User → 403; повторная отмена не возвращает место дважды |
| Логин возвращает JWT | POST /auth/login → 200 с token; проверены подпись, claims и время жизни |
| Защищённые маршруты требуют токен | Создание/чтение/отмена брони и запись событий: без токена → 401 |
| Запись событий только Admin | POST, PUT, DELETE /events: User → 403; Admin имеет доступ |
| Пароли не сохраняются открытым текстом | SHA-256 по условию задания, проверка хеша, тест чтения из хранилища |
| Новые правила и авторизация покрыты тестами | Доменные, сервисные, PostgreSQL- и HTTP-проверки; все проходят |

## Хорошие практики

- Генерация JWT находится в Infrastructure, интерфейс — в Application.
- Секрет, issuer, audience и срок действия находятся в конфигурации.
- Неверный логин и неверный пароль дают одинаковое сообщение.
- Отдельные коммиты: «Компоненты безопасности», «Обновление бизнес-логики и базы данных»,
  «Обновление API и авторизация», «Обновление тестов», «Проверка и оформление».
- Сохранение брони и мест атомарно через IUnitOfWork; EF Core не используется в сервисах Application.
- Тесты используют собственные базы; рабочая база не изменяется.
- Миграция проверена на уже существующих событиях и бронях: данные сохраняются.

## Дополнительные критерии «отлично»

- Репозиторий пользователей проверен на настоящей PostgreSQL, включая уникальность логина.
- В Swagger работает кнопка Authorize и Bearer-схема.
- Лимит вынесен в именованную константу `BookingService.MaxActiveBookings`.

## Дополнительные исправления безопасности

- Чтение брони проверяет владельца в Application. Чужая бронь скрыта за тем же 404,
  что и отсутствующая. Admin может читать любые брони.
- Все сеттеры Booking закрыты; тесты ограничений БД готовят специальные значения через EF Core.
- Основной JWT-ключ пустой, учебный — только в Development. Проверен реальный отказ
  запуска Production без ключа, до обращения к базе.
- Swagger показывает замки только для защищённых операций, учитывая AllowAnonymous.
- Добавлены регрессионные проверки доступа к чужой брони, инкапсуляции,
  конфигураций Production/Staging/Development и Swagger security.

## Ограничения учебного решения

- SHA-256 без соли выбран по заданию; в реальном проекте нужен специализированный password hasher.
- Публичный выбор Admin при регистрации разрешён заданием; в реальной системе такое назначение роли нужно закрыть.
- Учебный ключ находится только в appsettings.Development.json. Production без Jwt__Secret или иного явно заданного ключа не запускается.
- Семафор записи защищает один процесс API; для нескольких экземпляров нужна координация на уровне базы.
- Старые брони назначаются техническому владельцу без известного пароля. Их может отменить Admin.
