# Контракты сообщений

Общая библиотека для Bookings (издатель) и Events (подписчик).
Подключена к Application обоих сервисов и доступна их Infrastructure транзитивно.
Users и доменные слои от неё не зависят. Здесь нет EF Core, Kafka-клиента,
доменных сущностей или ссылок на проекты сервисов.

Имя топика: `KafkaTopics.BookingConfirmed` — `booking-confirmed`.

`BookingConfirmed` — неизменяемый sealed record с пятью полями:

| Поле | Тип | Значение |
| --- | --- | --- |
| BookingId | Guid | Идентификатор подтверждённой брони |
| EventId | Guid | Идентификатор события |
| UserId | Guid | Идентификатор владельца |
| SeatsCount | int | Число занятых мест, сейчас 1 |
| ConfirmedAt | DateTimeOffset | Время подтверждения в UTC |

Поля задаются при создании сообщения. В нём нет пароля, JWT, навигаций,
сущностей User/Event/Booking и внутренних данных сервисов.
Издатель должен передавать непустые идентификаторы, положительное число мест
и время сохранённого подтверждения; обработка некорректных сообщений — задача подписчика.

Формат JSON — стандартный System.Text.Json без переименования полей (PascalCase).
Издатель и подписчик должны использовать одинаковые настройки:

```json
{
  "BookingId": "11111111-1111-1111-1111-111111111111",
  "EventId": "22222222-2222-2222-2222-222222222222",
  "UserId": "33333333-3333-3333-3333-333333333333",
  "SeatsCount": 1,
  "ConfirmedAt": "2026-10-18T14:00:00+00:00"
}
```

Публикация после сохранения статуса Confirmed реализована в Bookings на этапе 4.
Ключ Kafka-сообщения — EventId в формате D, время — ProcessedAt подтверждённой брони.
Events читает сообщения в `BookingConfirmedConsumer` и уменьшает места;
повтор с тем же BookingId не применяется дважды.
