# Интеграционные тесты сервисов

При работающем Docker Desktop из корня репозитория:

```powershell
dotnet test ProjectWork.IntegrationTests --configuration Release
```

Testcontainers создаёт временный PostgreSQL 16 и три независимые базы:
users_tests, events_tests, bookings_tests. Подключения берутся исключительно
из этого контейнера, а не из рабочих appsettings.

Перед каждым тестом репозитория пересоздаётся соответствующая тестовая база;
схема создаётся миграциями. Коллекция выполняется последовательно.
После прогона контейнер удаляется.

Проверяются сохранение и чтение сущностей, tracking/reload, фильтры и пагинация,
уникальность логина, активные статусы броней и отсутствие внешних FK.
MigrationTests проверяет Up/Down, соответствие модели и единственную собственную таблицу.

Сценарии общей транзакции Events+Bookings, внешних FK и каскадного удаления из монолита
заменены проверками новых границ. HTTP-тесты отдельно подтверждают, что удаление события
не удаляет бронь, а до подключения Kafka подтверждение не изменяет места.
